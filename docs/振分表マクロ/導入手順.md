# 振分表マクロ 持参数の[確定して送る] 導入手順

## 導入するとどうなるか
- 振分表の[データ変換]ボタンが **[確定して送る]ボタン** に変わる（場所はそのまま）
- 最終決定が終わったら **このボタンを1回押すだけ**。中では次の順番で動く：
  1. 「◯/◯(◯)分の持参数を確定して送ります。よろしいですか？」と確認
  2. 空白セルがないかチェック → あれば止める（送らない・印刷しない）
  3. アプリへ送る
  4. **送れたときだけ** 振分表をB4で印刷
  5. 「◯件登録しました・印刷しました」と表示
- これまでの「会社サーバーに保存 → ブラウザを開く → ログイン → アップロード」は不要になる
- **保存や印刷では送らない**。D-2の仮の数字や作業途中の数字がアプリに送られることはない
- 押し忘れたら、19:30にしょうへいのLINEに通知が来る

事務所PCで1回だけやる作業。日ごとの振分表は前日のファイルをコピーして作っているので、**一度入れれば翌日以降のファイルにも引き継がれる**。

所要時間：15分くらい

## 0. 事前にアプリ側でやること（開発部）
- 本番に設定を追加：`ITEM_QUANTITY_API_TOKEN`（合言葉）・`OWNER_LINE_USER_ID`（通知先）
- Heroku Scheduler に `python manage.py check_item_quantity_received` を **毎日 10:30 UTC（=19:30 JST）** で登録

## 1. バックアップを取る
作業する振分表（いちばん新しい日のもの）を、同じフォルダにコピーしておく。
例：`振分表2026.10.5月.xlsm` → `振分表2026.10.5月_導入前.xlsm`
うまくいかなかったら、このコピーに戻せばOK。

## 2. 合言葉ファイルを置く
1. 導入セットの `lss_token.txt` を、**そのまま**会社サーバーの次のフォルダへコピーする（中身を開いて書き換えない）
   `\\192.168.111.250\Data\共有\◇LSS関係\`
2. コピーできたら、USBメモリとMacにある `lss_token.txt` は削除する

> 合言葉はマクロの中に書かない。LINE・メールで送らない。もし送ってしまったら開発部に言えば作り直せる（古い合言葉はすぐ使えなくなる）。

## 3. 振分表にマクロを入れる
1. 振分表を開いて `Alt + F11`（VBAの画面が開く）
2. **古い[データ変換]を消す**
   - 左の一覧の「標準モジュール」→「Module1」をダブルクリック
   - `Sub データアップロード用変換()` から、その下の `End Sub` までを選んで削除
     （`Sub 出力設定リンク()` の手前まで。消さないと名前がぶつかってエラーになる）
3. **新しいモジュールを取り込む**
   - メニューの「ファイル」→「ファイルのインポート」→ `LssAutoSend.bas` を選ぶ
   - 左の一覧に「LssAutoSend」が増えればOK
4. メニューの「デバッグ」→「VBAProject のコンパイル」を押す。何も出なければOK
   （エラーが出たら、画面を撮って開発部へ）
5. VBAの画面を閉じる
6. **ボタンの文字を変える**（任意）
   - 振分表シートの[データ変換]ボタンを右クリック →「テキストの編集」→「確定して送る」に書き換える
   - ボタンの登録先はそのままでOK（新しいマクロが同じ名前を引き継いでいる）
7. 振分表を上書き保存（.xlsm のまま）

## 4. 動作確認
**最終決定が終わった数字で**やること（押すと、その数字が本番のアプリに登録される）。

1. [確定して送る]を押す →「よろしいですか？」で「はい」
2. 「◯◯ 分の持参数を ◯◯ 件登録しました」「振分表をB4で印刷しました」と出て、振分表が印刷されればOK
   - 「アプリで管理しない店として読み飛ばし：なだや、武相、本町一丁目、千代田」も出る（この4店はアプリに店が登録されていないため。登録するかは別途決める）
3. LSSの「データアップロード」画面を開くと、持参数の欄に「最終受信 ◯/◯ ◯:◯◯（振分表の確定ボタン）」と出ている

## 5. 並行運用（1日）
いつもの手動アップロードもやって、数字が同じかを確かめる日。

1. D-1の最終決定 → [確定して送る]
2. LSSの「持参数一覧」でその日を開き、**3〜4店だけ**振分表の数字と見比べる（新木場・麹町・店・横浜組の1店がおすすめ）
3. いつもどおり手動アップロードもする（同じ数字で上書きされるだけなので問題なし）
4. 当日、日計表と出店状況ページがいつもどおりなら合格 → 次の日から手動アップロードはやめてOK

## 確定のあとで数字を直したいとき
直してから、もう一度[確定して送る]を押す。アプリの数字は最新のものに上書きされる（重複はしない）。振分表もまた印刷される。

## 困ったとき
| 出たメッセージ | やること |
|---|---|
| 空白のセルがあると…送りませんでした | 書いてある店・メニューのセルに 0 か数字を入れて、もう一度[確定して送る] |
| 合言葉ファイルが見つかりません | 手順2の場所・ファイル名を確認 |
| 認証に失敗しました | 合言葉の貼り間違い（空白・改行が入っていないか） |
| アプリに登録されていない店名 | 振分表に新しい店を足したとき。開発部に店名を伝える（アプリに店を登録するか、読み飛ばしに入れる） |
| 過去の日付のため振分表からは受け付けません | 前の日の振分表を開いている。今日以降の振分表で押す（過去分を直すときはLSSの画面から） |
| インターネットにつながらない可能性 | 印刷もされていない。ネットを確認してもう一度押す。急ぐときはLSSの画面から手動アップロードして、振分表は普通に印刷 |

- 19:30になっても次の営業日の分が届いていない／最後の送信が止められているときは、しょうへいのLINEに通知が来る
- 金曜は月曜分、連休前は連休明けの分を見る
