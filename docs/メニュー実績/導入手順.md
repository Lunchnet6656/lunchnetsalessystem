# メニュー表に「前回の実績」を出す 導入手順

## どうなるか
- メニュー表の週シートで、B列にメニュー名を入れると、**AS〜BD列にそのメニューの実績が自動で出る**
- 木曜日にベース設定数（AJ列）を決めるときの参考用。数字はLSSの日計表と受注から計算している
- 初めてのメニュー（または名前が1文字でも違う）は「初登場」と出る

「前回の週」は、そのメニューが前回出た週（ふつう月〜金の5日）を、**1日あたりにならした平均**。AJ列の設定数（1日の数）とそのまま比べられる。

| 列 | 見出し | 中身 |
|---|---|---|
| AS | 前回の週（初日） | 前回出た週の初日 |
| AT | 前回の週 日数 | その週に出た日数 |
| AU | 前回の週 1日平均 持参 | お店に持っていった数 |
| AV | 前回の週 1日平均 販売 | お店で売れた数 |
| AW | 前回の週 1日平均 別注 | 受注アプリの全部の注文。2026/3/26より前の週は「—」 |
| AX | 前回の週 1日平均 合計 | お店の販売＋別注 |
| AY | 前回の週 廃棄率 | お店の残り÷持参 |
| AZ | 前回の週 完売率 | 店×日のうち、そのメニューが売り切れた割合 |
| BA | 通算 1日平均 持参 | 2025/9以降に出た全部の週の平均（お店） |
| BB | 通算 1日平均 販売 | 同上 |
| BC | 通算 廃棄率 | 同上 |
| BD | 通算 回数 | 通算が何週分の平均か |

※お店の数字は、日計表を出す売り場だけ（「店」・配達・お試しは除く）。日計表を出さない売り先（カワイ等）は入らないので、AJ列の設定数より小さく出る。

## 1. 「メニュー実績」シートを作る（1回だけ）
1. メニュー表を開く
2. 「データ」タブ →「Webから」
3. URL に、開発部から受け取った **メニュー実績のURL**（`https://www.lunchnetsalessystem.com/api/menu-history.csv?key=…`）を貼り付けて「OK」
4. 「匿名」のまま「接続」
5. プレビューが出たら、右下の「読み込み」の▼ →「読み込み先…」→「テーブル」「新規ワークシート」→「OK」
6. できたシートの名前を **「メニュー実績」** に変える（シート名を右クリック →「名前の変更」。1文字でも違うと数式が動かない）
7. 「データ」→「クエリと接続」→ 右に出たクエリを右クリック →「プロパティ」→ **「ファイルを開くときにデータを更新する」** にチェック →「OK」

## 2. 週シートに数式を貼る（来週の週シートで1回だけ）
1. `メニュー実績_貼り付け用.xlsx` を開く
2. **AS2:BD22** を選んでコピー
3. メニュー表の来週の週シート（例：20261007）の **AS2** を選んで貼り付け
4. B列にメニュー名が入っている行の横に、実績が出ればOK

次の週からは、今までどおり**前の週のシートをコピーして新しい週を作れば、数式もついてくる**。

## 3. ふだんの使い方（木曜日）
- メニュー表を開くと、実績が自動で最新になる（手動なら「データ」→「すべて更新」）
- 実績はアプリ側で1日1回計算している（その日の分は含まない）

## 困ったとき
| 症状 | やること |
|---|---|
| 全部「初登場」になる | シート名が「メニュー実績」か確認。データ→すべて更新 |
| 一部だけ「初登場」 | メニュー名がLSSの日計表と1文字違う（空白・★・カッコなど） |
| 更新で「アクセスできません」 | URLの key が違う／インターネット接続を確認 |
| 数字が古い | データ→すべて更新 |
